# Archer 12-Week Engineering Delivery Map

| Week | Engineering outcome |
|---|---|
| 1 | Architecture, repository, CI, DB model, auth foundation, website foundation |
| 2 | Website foundation, Driver onboarding, Admin/Driver UI foundation |
| 3 | Ride management, driver profiles, tier administration |
| 4 | Tier routing, admin switches, dispatch, lifecycle, audit |
| 5 | Pricing, fleet, availability, security foundation |
| 6 | Preferred driver, broadcast/reassignment, owner-operator |
| 7 | Ride clock, wait/minimum rules, Airport Transfer, Square |
| 8 | Payroll, cash/card/Venmo reconciliation, Client Car/walk-around |
| 9 | Client auth + Vehicle/Tier/Trip booking |
| 10 | Review/confirmation, My Trips, payment/customer history |
| 11 | Production hardening, hybrid packaging, store assets |
| 12 | Device testing, submission/resubmission support, UAT, launch/handover |

## Working method
Each milestone should be a vertical slice:
UI + API + database + authorization + validation + integration + tests + QA.

Weekly demo outputs should be working functionality, not only screenshots or static UI.

## Change control
Anything outside approved scope should be recorded as:
- clarification
- defect
- change request
- future phase item

Do not silently absorb material scope expansion into the current milestone.
